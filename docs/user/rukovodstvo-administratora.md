# Руководство администратора WMS

Документ для администраторов склада и IT: настройка системы, пользователи, права, справочники и интеграция. Не требует знания программирования.

---

## 1. Раздел «Администрирование»

**Путь:** Администрирование (или `/admin`).

Хаб с карточками всех подсистем:

| Раздел | Путь | Назначение |
|--------|------|------------|
| Настройки | `/settings` | Склад, модули, ТСД, очистка данных |
| Пользователи | `/admin/users` | Учётные записи |
| Роли | `/admin/roles` | Права доступа |
| Статусы | `/admin/statuses` | Названия и цвета статусов |
| Метаданные | `/admin/meta` | Поля справочников и документов |
| Меню | `/admin/nav` | Левое меню: порядок, иконки |
| Интеграция | `/admin/integration` | Обмен с 1С, webhook, API-ключи |
| Правила размещения | `/admin/putaway` | Алгоритмы подбора ячейки на ТСД |

Доступ к администрированию есть только у пользователей с правом **«Администрирование»** (обычно роль «Администратор»).

## 2. Настройки склада

**Путь:** Администрирование → Настройки.

### Склад

| Поле | Назначение |
|------|------------|
| Название | Отображается во вкладке браузера |
| Код | Краткий код склада, тоже во вкладке: «Название · Код» |

### ТСД и учёт

| Параметр | Назначение |
|----------|------------|
| API-ключ ТСД | Секрет для регистрации терминалов (ТСД → Устройство) |
| Разрешить отрицательные остатки | Снять блокировку при недостатке товара при отборе/отгрузке |
| Движений на обзоре | Сколько последних движений показывать на главной (1–100) |

### Модули

**Всегда включены** (нельзя отключить):

- НСИ, пользовательские интерфейсы, остатки, операции, ТСД, администрирование

**Можно включать и выключать:**

| Модуль | Что скрывается при выключении |
|--------|-------------------------------|
| Приёмка | Раздел приёмки, ТСД-приёмка, связанные API |
| Отгрузка | Раздел отгрузки, ТСД-отбор |
| Топология | План склада |
| Партии | Справочник партий, учёт по срокам годности |

При выключенном модуле пользователь видит страницу «Модуль выключен», даже если у роли есть право.

### Очистка базы

Удаляет **пользовательские данные**:

- документы приёмки и отгрузки, операции, остатки, движения;
- товары, ячейки, зоны, контрагентов, партии, паллеты и т.п.

**Сохраняется:**

- пользователи, роли, настройки склада;
- предопределённые справочники (единицы, типы ТН, модели учёта).

Для подтверждения нужно ввести слово **ОЧИСТИТЬ**. Используйте для сброса тестового контура или перед загрузкой новых мастер-данных.

## 3. Пользователи

**Путь:** Администрирование → Пользователи.

### Создание пользователя

1. Нажать **«Создать пользователя»**.
2. Указать логин, имя, пароль, **роль**.
3. Сохранить.

У каждого пользователя **ровно одна роль**. Права операций настраиваются в роли, а не у пользователя напрямую.

### Управление учётной записью

| Действие | Как |
|----------|-----|
| Сменить роль | Выбрать роль в таблице → OK |
| Отключить | Кнопка «Отключить» — пользователь не сможет войти |
| Включить снова | Кнопка «Включить» |

## 4. Роли и права

**Путь:** Администрирование → Роли.

### Системная роль

- **Администратор** (`admin`) — полный доступ, удалить нельзя.
- Все права включены по умолчанию.

### Пользовательские роли

- Создаются кнопкой **«Создать роль»**: код, название, описание.
- Удалить можно только **пустую** роль (без назначенных пользователей).
- Редактирование прав — **«Изменить права»** → матрица галочек.

> Изменения прав применяются у пользователя при **следующем переходе** по сайту (обновление страницы или переход в другой раздел).

### Группы в матрице прав

#### Модули

Доступ к основным разделам веб-интерфейса. У большинства модулей два уровня:

| Уровень | Что даёт |
|---------|----------|
| Просмотр | Открыть раздел, читать данные |
| Редактирование | Создавать, изменять, удалять |

Модули: приёмка, отгрузка, остатки, операции, администрирование, топология, партии, веб-интерфейс ТСД.

#### НСИ

| Право | Что даёт |
|-------|----------|
| Обзор НСИ | Видеть хаб `/nsi` |
| Каждый справочник | Отдельная строка: номенклатура, ячейки, контрагенты… |
| Редактирование | Создание и изменение записей справочника |

Пользовательские справочники и документы в НСИ появляются в матрице **автоматически** после создания в метаданных.

#### Пользовательские интерфейсы

| Право | Что даёт |
|-------|----------|
| Раздел меню | Доступ к хабу `/m/…` |
| Справочник в разделе | Просмотр и редактирование `/catalog/…` |
| Документ в разделе | Просмотр и редактирование `/doc/…` |

#### ТСД

| Право | Операция на терминале |
|-------|----------------------|
| Веб-интерфейс ТСД | Вход в `/tsd` |
| Приёмка | ТСД → Приёмка |
| Размещение | ТСД → Размещение |
| Свободный скан | Размещение без выбора из списка задач |
| Отбор | ТСД → Отбор |
| Перемещение | ТСД → Перемещение |

### Рекомендуемые профили ролей

| Роль | Модули | НСИ | ТСД |
|------|--------|-----|-----|
| Кладовщик | Приёмка, отгрузка, остатки (просмотр), операции (просмотр) | Ячейки, ТН, штрихкоды (просмотр) | Приёмка, размещение, отбор, перемещение |
| Менеджер склада | Все складские + редактирование | Все нужные справочники | По необходимости |
| Оператор НСИ | Остатки (просмотр) | Номенклатура, контрагенты (редактирование) | — |
| Только просмотр | Просмотр без «редактирование» | Только просмотр | — |

### Два уровня блокировки

1. **Модуль выключен** в настройках → «Модуль выключен».
2. **Нет права у роли** → «Доступ запрещён».

Оба условия должны быть выполнены для доступа.

## 5. Статусы

**Путь:** Администрирование → Статусы.

Предопределённые статусы задаются системой; администратор может:

- изменить **название** и **цвета** бейджа;
- указать, в каких **потоках** статус доступен (приёмка, отгрузка, размещение, ТН, перемещение);
- **деактивировать** — статус нельзя выбрать в новых документах.

### Справочник статусов

| Код | Типичное название | Потоки |
|-----|-------------------|--------|
| DRAFT | Новый | Приёмка, отгрузка, размещение, перемещение |
| RELEASED | К исполнению | Приёмка, отгрузка, размещение |
| AVAILABLE | Свободен | Товарные носители |
| ACCEPTED | Принят | Приёмка, ТН |
| PLACED | Размещён | Приёмка, ТН, размещение |
| POSTED | Проведён | Отгрузка, размещение, перемещение |
| COMPLETED | Завершён | Приёмка, размещение (устаревший для приёмки) |
| CANCELLED | Отменён | Все потоки |

Не удаляйте статусы из потоков без понимания последствий — документы могут «застрять» без возможности перевода.

## 6. Метаданные

**Путь:** Администрирование → Метаданные.

Здесь настраиваются **поля** справочников и документов.

### Типы сущностей

| Тип | Хранение | Примеры |
|-----|----------|---------|
| Системный справочник | Таблицы Prisma | Номенклатура, ячейки, зоны |
| Системный документ | Таблицы Prisma | Приёмка, отгрузка |
| Пользовательский справочник | EAV (гибкие поля) | Создаётся администратором |
| Пользовательский документ | EAV | Создаётся администратором |

Системные сущности **нельзя удалить**; можно добавлять **дополнительные** (несистемные) атрибуты к приёмке, отгрузке и др.

### Создание пользовательского справочника

1. **Метаданные → «Создать справочник»**.
2. Код (латиница, `snake_case`), название, множественное число.
3. **Раздел меню** — куда попадёт в навигации:
   - конкретный пользовательский раздел;
   - **НСИ** — справочник на хабе НСИ без отдельного пункта меню.
4. После создания — настроить поля в карточке сущности.

По умолчанию создаётся поле «Название». Остальные атрибуты добавляются вручную.

### Создание пользовательского документа

1. **Метаданные → «Создать документ»**.
2. Код, название, раздел меню (или НСИ).
3. По умолчанию: секции «Шапка» и «Основные», поля **Номер**, **Дата**, **Комментарий**.

Пользовательские документы:

- список, создание, редактирование карточки;
- **без** табличной части, проведения и влияния на остатки.

### Настройка атрибутов

В карточке сущности (`/admin/meta/{код}`):

| Параметр | Назначение |
|----------|------------|
| Тип | Строка, число, дата, логический, ссылка на справочник, перечисление… |
| Секция | Группа полей на форме |
| Обязательный | Нельзя сохранить без значения |
| В списке / В форме | Видимость в таблице и на карточке |
| Порядок | Сортировка полей |

Системные атрибуты (помечены как системные) нельзя удалить; их подписи синхронизируются при обновлении приложения.

### Права после создания

Новые пользовательские справочники и документы **автоматически** появляются в матрице ролей (группы «НСИ» или «Пользовательские интерфейсы»). Назначьте права нужным ролям.

## 7. Меню

**Путь:** Администрирование → Меню.

Управление **левым меню** приложения.

### Системные пункты

Обзор, НСИ, Остатки, Операции, Приёмка, Отгрузка, Администрирование, ТСД — встроены в систему. Их можно:

- менять **порядок**;
- менять **подпись** и **иконку**;
- скрывать (если поддерживается настройкой пункта).

### Пользовательские разделы

Создаются для группировки **своих** справочников и документов:

1. **Меню → «Добавить раздел»** (или аналогичная кнопка).
2. Код, название, иконка.
3. В **Метаданных** при создании справочника/документа выбрать этот раздел.

Справочники **не добавляются** напрямую в меню — только через метаданные.

### Иконки

Настраиваются на той же странице «Меню». Отдельная страница «Иконки» перенаправляет сюда.

## 8. Правила размещения

**Путь:** Администрирование → Правила размещения.

Влияют на подбор **целевой ячейки** при размещении ТН на ТСД.

### Правила

| Правило | Логика |
|---------|--------|
| К такому же товару | Ячейка, где уже лежит этот товар (на том же ТН) |
| В пустую ячейку | Свободная ячейка в зоне хранения |

Для каждого правила:

- **Приоритет** — меньшее число проверяется раньше;
- **Вкл.** — правило участвует в подборе.

### Поведение на ТСД

| Настройка | Эффект |
|-----------|--------|
| Ручной выбор ячейки | Оператор может указать ячейку вместо предложенной |
| «К размещению» после приёмки | Кнопка перехода к размещению после завершения приёмки паллеты |

## 9. Интеграция

**Путь:** Администрирование → Интеграция.

Для обмена с внешними системами (1С, ERP, webhook-подписчики).

### Webhook

- URL получателя событий.
- HMAC-секрет для подписи.
- Включение/выключение.

### 1С

- Endpoint адаптера для обмена событиями с 1С.

### Outbox / Inbox

| Очередь | Назначение |
|---------|------------|
| Outbox | Исходящие события из WMS |
| Inbox | Входящие события в WMS |

Кнопки:

- **Слить outbox** — отправить накопленные исходящие;
- **Повторить failed** — переотправить/переобработать ошибочные записи.

### API-ключи

Создание ключей для внешних систем, обращающихся к API WMS. Храните ключи в безопасном месте; при компрометации — отозвать и создать новый.

> Детали форматов сообщений — в [integration-contract.md](../integration-contract.md) (для интеграторов).

## 10. НСИ vs меню vs метаданные — как связано

```
┌─────────────────────────────────────────────────────────┐
│  МЕТАДАННЫЕ — что создать (справочник / документ, поля) │
└──────────────────────────┬──────────────────────────────┘
                           │
           ┌───────────────┴───────────────┐
           ▼                               ▼
   Привязка: НСИ                  Привязка: раздел меню
   (/nsi, /catalog/…)             (/m/…, вкладки раздела)
           │                               │
           └───────────────┬───────────────┘
                           ▼
              РОЛИ — кому видно и кто редактирует
                           │
                           ▼
              МЕНЮ — порядок и иконки в навигации
```

| Вопрос | Ответ |
|--------|-------|
| Где создать свой справочник? | Метаданные → Создать справочник |
| Где он появится в интерфейсе? | На хабе НСИ или в пользовательском разделе — зависит от привязки |
| Как дать доступ кладовщикам? | Роли → галочки в «НСИ» или «Пользовательские интерфейсы» |
| Как добавить пункт в левое меню? | Меню → новый раздел; затем привязать справочник в метаданных |

## 11. Типовые задачи администратора

### Подключить нового сотрудника

1. Пользователи → создать учётную запись, назначить роль.
2. Если нужной роли нет — Роли → создать, настроить матрицу.
3. Сотрудник входит и проверяет доступные разделы.

### Включить приёмку на складе

1. Настройки → включить модуль **Приёмка**.
2. Роли → выдать права «Приёмка» (просмотр + редактирование) и «ТСД: приёмка», «ТСД: размещение».
3. Настройки → проверить **API-ключ ТСД**.
4. На терминале зарегистрировать устройство.

### Добавить поле в документ приёмки

1. Метаданные → открыть сущность **inbound**.
2. Добавить атрибут (несистемный): тип, секция, видимость.
3. Поле появится в форме приёмки без перезапуска.

### Создать раздел «Качество» со своим справочником

1. Меню → создать раздел «Качество».
2. Метаданные → создать справочник, привязать к разделу «Качество».
3. Настроить поля справочника.
4. Роли → выдать права на раздел и справочник.

### Сбросить тестовые данные

1. Настройки → Очистка базы → ввести **ОЧИСТИТЬ**.
2. Пользователи и роли сохранятся; документы и остатки удалятся.

---

## 12. Безопасность — рекомендации

- Роль **Администратор** — только для доверенных лиц.
- Пароли — индивидуальные, не передавать между сотрудниками.
- API-ключ ТСД и ключи интеграции — не публиковать; менять при утечке.
- Отключайте учётные записи уволенных сотрудников, не удаляя историю.
- Минимальные права: давать только то, что нужно для работы (принцип наименьших привилегий).

## 13. Частые вопросы

**Пользователь не видит новый справочник.**  
Проверьте: модуль включён; в роли есть право на справочник или раздел меню; справочник привязан к нужному разделу.

**Права изменили, но не работает.**  
Попросите пользователя обновить страницу или перейти в другой раздел.

**Где синхронизировать системные метаданные?**  
Автоматически при первом запуске (seed) и обновлении системы. Отдельной кнопки в интерфейсе нет.

**Можно ли удалить системный справочник?**  
Нет. Можно только скрыть доступ через роли и меню.

**Чем пользовательский документ отличается от приёмки?**  
Приёмка — системный документ со строками, статусами и влиянием на остатки. Пользовательский — произвольная форма без проведения.

**К кому за технической интеграцией с 1С?**  
К IT / интегратору; форматы — в integration-contract.md.
